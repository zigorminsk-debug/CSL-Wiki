# CSL Wiki — Android-клиент Confluence

Новый нативный Android-клиент **только для https://w.csl.by**. Java + Android SDK,
без Capacitor, Node-прокси, React, npm и встроенных ключей/паролей.
Jira не входит в эту версию: пользователь выбрал только Confluence.

## Возможности первой версии

- Вход на **настоящей странице Confluence** в защищённом WebView.
- Проверка авторизованного пользователя через `/rest/api/user/current`.
- Пространства и страницы с постраничной загрузкой.
- Поиск Confluence по заголовку и тексту через CQL.
- Чтение статей: заголовки, списки, таблицы, код и обычные изображения.
- Сохранение текста статей на устройстве и история чтения.
- Поиск по локальному кэшу при недоступности сети.
- Обновление статьи с сервера и открытие оригинала в браузере.
- Настройка context path, явные сообщения о сети/TLS/HTTP/HTML и копирование
  диагностики **без cookies и паролей**.
- Выход удаляет сессию, кэш статей и данные WebView.

Это клиент **для чтения**. Редактирование, очередь изменений, вложения офлайн,
полное отображение макросов и Jira намеренно не реализованы.

## Почему вход устроен именно так

Вместо предположения, что сервер принимает Basic Auth, клиент открывает
`https://w.csl.by/login.action`. Пользователь вводит логин/пароль непосредственно
в форму сервера. Android CookieManager хранит полученную сессию; нативные
HTTPS-запросы REST API используют её cookies. Пароль не читается приложением,
не сохраняется в его настройках и не передаётся стороннему прокси.

После входа нужно нажать **«Проверить вход»**. Anonymous-ответ, HTML и HTTP 401
не считаются успехом. Переходы REST API на страницу логина не проглатываются.

Если сервер установлен в подпапке, укажите, например,
`https://w.csl.by/confluence` в параметрах подключения. `/rest/api` добавляется
клиентом автоматически. Адрес `/wiki` подходит только если это реальный путь
установки, а не по аналогии с Confluence Cloud.

Поддерживается локальная форма входа на w.csl.by. Внешний SSO/IdP и сторонние
ресурсы заблокированы; для них потребуется отдельная интеграция.

## Как проверить на телефоне

1. Установите APK и откройте **CSL Wiki**.
2. Нажмите **«Войти в Confluence»**, заполните серверную форму и войдите.
3. Нажмите **«Проверить вход»** — после проверки появятся пространства.
4. Откройте статью, нажмите **«Сохранить»**.
5. Включите авиарежим и откройте **«Сохранённое»** — текст должен читаться.
6. При проблеме: меню **⋯ → Скопировать диагностику**. Не присылайте пароль.

Пакет приложения: `by.csl.wiki`. Он отличается от старого `com.csl.wiki` и
`com.csl.wiki.debug`, поэтому старые приложения не нужно удалять. Локальные
данные прежних клиентов не импортируются.

## Безопасность и ограничения

- Только HTTPS и точный hostname `w.csl.by`; URL с логином/паролем, сторонним
  host, нестандартным портом, query/fragment в base URL не принимаются.
- Проверка TLS штатная: недоверенные сертификаты не обходятся. Для внутреннего
  DNS/VPN/корпоративного CA нужна настройка устройства администратором.
- В редакторе статей нет JavaScript, файлового доступа или native JS bridge.
  CSP запрещает скрипты, формы, фреймы и внешние сетевые ресурсы.
- Страница входа использует JavaScript сайта; сторонние cookies выключены.
- Пароль не сохраняется, но **сессионные cookies сохраняются** в app-private
  WebView storage для повторного входа. Это не аппаратный secure vault.
- Текст статей хранится в app-private SQLite, без дополнительного шифрования;
  Android backup выключен. Используйте блокировку экрана на телефоне.
- При смене аккаунта, context path или выходе кэш очищается. Удаление серверных
  прав не может отозвать уже сохранённую офлайн-копию на устройстве.
- Сложные Confluence-макросы не исполняются. Кнопка **↗** открывает оригинал во
  внешнем браузере, где может понадобиться отдельный вход.
- Кэш хранит тексты открытых статей. **«Убрать из сохранённых»** не стирает копию
  из истории; для полного удаления используйте очистку кэша или выход.
- Поиск офлайн проверяет до 100 совпадений среди локальных статей; SQLite не
  является зеркалом всего сервера. Пространства требуют сеть.

## Сборка и проверки

Нужны JDK 17, Android SDK 35 и доступ к Google Maven/Maven Central.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

GitHub Actions (`.github/workflows/android.yml`) запускает тесты, Android Lint,
собирает устанавливаемый debug APK и публикует артефакт **CSL-Wiki-Android** с
SHA-256. Отчёты — отдельный артефакт **Android-check-reports**. Debug-подпись
предназначена для тестирования, не для гарантированных обновлений production.
В релизный APK ключи подписи не вшиты; для production нужен собственный keystore
вне Git и отдельная безопасная настройка CI.

Тесты покрывают URL/host policy, CQL escaping, UTF-8, anonymous/current-user,
распознавание HTML/битого JSON, ограничение размера ответа и CSP статьи.
**Они не подменяют проверку реального входа на w.csl.by с телефона.** В среде
разработки доступ к этому хосту запрещён сетевой политикой. Ни авторизация на
живом сервере, ни физическое Android-устройство здесь не объявляются проверенными.
