## Почему возникла ошибка на скриншоте

`Unexpected token '<', "<!DOCTYPE ..." is not valid JSON` означает, что клиент
получил HTML вместо ответа REST API. Это **не доказательство неверного пароля**.

В исходном коде обнаружены три независимых дефекта:

1. **В APK по умолчанию использовался `/api/csl` на локальном origin WebView.**
   В APK упаковывается `public/`, а не Node-процесс. Следовательно, Node-прокси
   внутри приложения отсутствует. Локальный asset-сервер может вернуть оболочку
   HTML, которую код без проверки передавал в `res.json()`.
2. **Проверка пользователя вызывала `/wiki/api/v2/user/current`.**
   Для Confluence current user используется REST v1: `/rest/api/user/current`
   для Server/Data Center и `/wiki/rest/api/user/current` для Cloud.
3. **Смена API path на `/rest/api` не включала настоящий v1-адаптер.**
   Код продолжал обращаться к v2-маршрутам `/spaces` и `/pages`, которые
   не соответствуют v1-маршрутам `/space` и `/content`.

HTML также мог приходить от reverse proxy, страницы SSO или неверного context
path сервера. Без доступа к серверу нельзя установить, какой именно HTML
вернулся в показанном запросе. Пароль пользователя не запрашивался и не проверялся.

## Что исправлено

### Вход и транспорт

- Включён `CapacitorHttp`, в native-режиме автоматически выбирается прямой URL
  Confluence, без относительного Node-прокси и ограничений браузерного CORS.
- В браузере сохранён same-origin Node-прокси, есть ручной direct-режим.
- Исправлен endpoint проверки пользователя; anonymous-ответ не считается входом.
- Реализован отдельный REST v1-адаптер: пространства по ключу, страницы через
  content API, v1 payload для создания и изменения, раскрытие storage body.
- Cloud v2 сохранён; исправлена загрузка полных тел страниц при синхронизации,
  убран неработающий CQL-параметр из v2 pages API.
- Добавлена пагинация с переносом только параметров cursor/start: стороннему
  хосту из `_links.next` пароль не отправляется.
- HTML, пустые ответы, HTTP 204, неверный JSON и HTTP-ошибки обрабатываются явно.
- Basic auth кодируется через UTF-8, а не через несовместимый с кириллицей btoa.
- Проверяется HTTPS URL и формат API path. Подключение не сохраняется как
  успешное до проверки пользователя; повторная отправка формы блокируется.

### Данные и синхронизация

- Кэш/очередь/закладки разделены по серверу, имени пользователя и API path;
  демо отделено от настоящих аккаунтов.
- Приватные API-ответы исключены из общего Service Worker Cache API.
- В offline shell добавлены пропущенные auth.js и update.js; версия кэша повышена.
  В native-приложении новый Service Worker не регистрируется.
- Ошибка pull больше не замалчивается и не продвигает lastPull.
- Курсор успешного pull фиксирует начало запроса, а не конец обработки.
- Несохранённое локальное тело страницы не затирается новой серверной версией;
  конфликт блокирует отправку. Ошибки push видны, очередь сохраняется.
- При реальном update проверяется ожидаемая версия, чтобы не перезаписать
  чужое изменение между pull и push.
- После выхода автоматическая синхронизация по событию online не запускается;
  смена аккаунта блокируется во время активной синхронизации.
- Выход очищает отображённые страницы/чат; устаревшие ответы чтения проверяют
  принадлежность сеансу. Повторный вход не добавляет слушателей статуса заново.

### Безопасность и сборка

- Прокси ограничен разрешёнными origin (`CSL_ALLOWED_ORIGINS`) и REST-маршрутами.
  Он не следует редиректам с авторизацией, ограничивает размер тела и время запроса.
- Удалена неработающая настройка CSL_INSECURE: Node fetch не применял переданный
  https.Agent. Проверка TLS не отключается.
- Значения id экранируются и в HTML-атрибутах.
- Отключён Android backup, чтобы не включать локальные пароли в резервные копии.
- Ключ/пароли подписи не импортированы; CI получает их из Actions secrets.
  Без secrets обычный branch build собирает debug APK, tag build требует подпись.
- CI использует npm ci и запускает тесты. Исправлены устаревшие инструкции,
  утверждавшие, что Node-сервер находится внутри APK.
- В APK недоступная Node-демонстрация отключена с пояснением.

## Проверки

- `npm test`: 10 тестов API/прокси и 22 проверки сценариев offline/sync,
  включая сбои pull, конфликт версий и изоляцию аккаунтов.
- `npx cap sync android`: успешно копирует assets, применяет native HTTP config
  и обновляет Android bridge.
- `node --check`: проверка синтаксиса JS в public и server.
- `npm audit`: выявлены 5 уязвимостей инструментов разработки Capacitor 6
  (3 moderate, 1 high, 1 critical; в дереве зависимостей есть tar 6).
  Пробная major-подмена tar ломает `cap sync` из-за несовместимого default export;
  она откачена. Нужна отдельная согласованная миграция Capacitor CLI/core/android,
  Android SDK/JDK и повторная проверка APK, а не `npm audit fix --force` вслепую.

Полная Gradle-сборка и тест на физическом Android здесь не выполнялись:
в среде нет JDK/Android SDK и запрещён доступ к их стандартным источникам загрузки.
Доступ к `w.csl.by` также ограничен сетевой политикой среды. Тест native-режима
проверяет выбор транспорта/URL в JS, а не реальный Android HTTP bridge.

## Что ещё требует работы

Это обзор с исправлением найденных дефектов, а не гарантия отсутствия всех ошибок.

- Требуется проверка входа на реальном сервере и на телефоне после пересборки APK.
  Неизвестны версия Confluence, context path, требования SSO/Basic auth и TLS.
- Пароли пока хранятся в localStorage: нужен secure-storage/token подход.
- Старый общий IndexedDB оставлен нетронутым и не мигрирует автоматически:
  нельзя безопасно определить владельца старых страниц и отложенных изменений.
  Перед очисткой/удалением приложения сделайте резервную копию несинхронизированных правок.
- Нет интерфейса ручного разрешения конфликтов; конфликтные элементы остаются в очереди.
- Нет полного согласования удалённых страниц и зависимых операций над local-only
  страницами; реальная синхронизация пока обходит все доступные страницы.
- Storage HTML отображается как текст, не как форматированная статья.
- Прокси не имеет собственной пользовательской авторизации и rate limiting;
  его следует размещать за контролем доступа. Allowlist не заменяет аутентификацию.
- Старый ключ подписи находится в истории другой ветки. Не считать его секретным;
  перенос в secrets не отменяет прежнего раскрытия. Нужен план смены подписи,
  учитывающий, что новый ключ обычно не обновит старый sideloaded APK.

## Что вводить после пересборки

Если ваш сервер — Confluence Server/Data Center без дополнительного context path:

- Server URL: `https://w.csl.by`
- Advanced → API path: `/rest/api`
- Ваше настоящее имя пользователя Confluence и пароль.

Для установки с context path добавьте его только к Server URL. Если используется
Cloud, укажите Cloud URL, `/wiki/api/v2`, email и API token. Если сервер требует
только SSO, текущего Basic-входа будет недостаточно. Не отправляйте пароль в чат.
